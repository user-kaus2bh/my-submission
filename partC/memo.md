# Part C — Decision memo: casual-register replies for Hindi, Kannada, Tamil, Telugu, Bengali, Marathi

**Chosen path: (b) — small (≤1B) inference-time rewriter model** run after
the main model. It only touches *style*, never content, which makes both
the risk profile and the rollback story simple: if it underperforms, skip
it and serve the original (formal but correct) output — nothing about the
main model changes.

## Assumptions

1. The main model's outputs are already linguistically correct and
   factually fine in all six languages — the gap is register/style only,
   not content quality. (If this is false, a rewriter can't fix it; this
   is the load-bearing assumption for choosing (b) over (a).)
2. "No external API budget" means no *paid third-party* LLM APIs — we can
   still use our own already-deployed main model to generate synthetic
   supervision (self-distillation via few-shot prompting), which costs
   only compute we already have.
3. A ≤1B model can be meaningfully fine-tuned on a narrow style-transfer
   task (formal→casual rewrite) with far less data than a general SFT run
   would need, because the task is narrow (rewrite, not generate).
4. The Hindi/Kannada reviewer's judgment ("does this sound natural") is
   the ground truth for those two languages; for the other four, we have
   no ground truth and must say so explicitly rather than pretend
   otherwise.

## Back-of-envelope arithmetic

- **Data volume:** target ~8,000 synthetic (formal, casual) rewrite pairs
  per language × 6 languages ≈ **48,000 pairs**. At ~60 tokens/pair, that's
  ~5.8M tokens — generated by few-shot prompting the main model itself, no
  paid API needed. At a rough batched generation rate of ~20 pairs/min,
  that's ~2,400 minutes ≈ **40 GPU-hours** of generation, comfortably
  inside the 2-week A100 window.
- **Training cost:** a ≤1B model fine-tuned on 48K short examples for 2-3
  epochs is small — rough estimate **3-6 GPU-hours** total on one
  A100-80GB. Leaves ~11-12 of the 14 available days for iteration,
  re-training on reviewer feedback, and buffer before the 3-week launch
  review.
- **Reviewer throughput:** 10h/week × 3 weeks = **30 reviewer-hours**
  total, Hindi + Kannada only. At ~40-60 quick naturalness ratings/hour,
  that's **~1,200-1,800 reviewed samples** across those two languages —
  enough for a real quality read on 2 of 6 languages. **Zero direct human
  signal on Tamil, Telugu, Bengali, Marathi** — the single biggest risk in
  this plan, stated plainly rather than glossed over.
- **Serving cost:** one extra ≤1B forward pass per response, in fp16 —
  tens of milliseconds, a small fraction of the main model's own serving
  cost. Cheap bolt-on, not a re-serve of the whole response.

## Success metric (numeric threshold)

For **Hindi and Kannada only** (the only languages with a ground-truth
reviewer): on a random 200-sample batch,
- **≥75%** rated ≥4/5 on "sounds natural/casual, not textbook," **and**
- **≥95%** rated "meaning preserved" (no factual/semantic drift from the
  rewrite step).

Both thresholds must clear — a rewriter that sounds casual by breaking
meaning is worse than no rewriter. For the four unreviewed languages: an
automatic stylistic-similarity proxy only, tracked but **not** a launch
gate, since we have no way to validate it means what we hope it means.

## Kill criterion

**By end of Week 1:** if an early n=50 Hindi/Kannada spot-check shows
**<50%** passing "natural + meaning preserved," kill this path. A rewriter
that can't clear a low bar early, given only 30 total reviewer-hours to
improve it, won't clear a high bar by Week 3 — and killing early still
leaves ~2 weeks to fall back to prompt-engineering-only (path c) before the
launch review. **At any point:** if any unreviewed language's automatic
proxy shows near-total rewrite failure (gibberish/degenerate output), pull
that language from launch scope rather than ship it broken and unreviewed.

## First experiment, Day 1

Before generating anything at scale: spend the reviewer's very first
session hand-writing ~20 gold formal→casual pairs each for Hindi and
Kannada. This (a) fixes an operational definition of "casual enough" with
an actual native speaker before building a pipeline around a guess, and
(b) becomes the few-shot seed set for prompting the main model to generate
the larger synthetic dataset. Run in parallel with a first rough zero-shot
casualization pass for the four unreviewed languages, so no A100 time sits
idle waiting on the reviewer.
